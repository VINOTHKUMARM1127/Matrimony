# Wedring Matrimony — Supabase Package

Everything your app and admin panel need to talk to Supabase: SQL schema, RLS,
triggers, business-logic functions, cron jobs, and 5 Edge Functions.

## What's in here

```
supabase/
  migrations/
    20260701120000_wedring_matrimony_schema.sql   <- tables, enums, RLS, triggers, views, seed data
    20260701120100_cron_schedule.sql              <- pg_cron: nightly distribution + hourly expiry sweep
    20260701120150_subscription_lifecycle_functions.sql <- activate/queue + expire/advance plan logic
  functions/
    razorpay-create-order/   <- POST: creates a Razorpay order + pending payment row
    razorpay-webhook/        <- Razorpay calls this; verifies signature, activates the plan
    r2-presigned-upload/     <- POST: signed PUT URL so the app can upload a photo straight to R2
    r2-delete-photo/         <- POST: deletes an R2 object + its profile_photos row together
    daily-distribution-cron/ <- optional HTTP trigger for the nightly jobs (alt. to pg_cron)
    _shared/cors.ts
```

## What got created in the database

**28 tables** — lookups (`religions`, `castes`, `sub_castes`, `countries`, `states`,
`districts`, `cities`, `occupations`, `education_levels`, `rasi`, `nakshatra`, `lagnam`,
`gothram`, `mother_tongues`), core (`admin_users`, `profiles`, `registration_meta`,
`profile_contact`, `user_family`, `user_horoscope`, `user_lifestyle`,
`partner_preferences`, `profile_photos`), membership/payment (`membership_plans`,
`user_subscriptions`, `subscription_queue`, `subscription_history`, `payments`,
`failed_payments`, `contact_credit_transactions`, `interest_credit_transactions`), and
match/distribution (`distribution_config`, `distributed_profiles`, `distribution_logs`,
`interests`, `not_interested`, `compatibility_scores`).

**16 enums**, **RLS enabled + policies on every table**, **~15 functions** (compatibility
scoring, distribution engine, credit spend, interest send/respond, admin actions,
subscription activation/expiry), **triggers** that auto-run onboarding distribution when
a profile/subscription is created, **3 views** (`user_dashboard_summary`,
`admin_stats_view`, `revenue_summary`), and **seed data** (all religions, all 36 Indian
states/UTs, starter castes/occupations/education levels, full rasi/nakshatra/lagnam/
gothram lists, default membership plans + distribution counts).

## Deploy

```bash
# from your project root, with the Supabase CLI installed and linked to your project
supabase link --project-ref <your-project-ref>

supabase db push                    # runs all 3 migrations in order

supabase functions deploy razorpay-create-order
supabase functions deploy razorpay-webhook --no-verify-jwt   # Razorpay can't send a Supabase JWT
supabase functions deploy r2-presigned-upload
supabase functions deploy r2-delete-photo
supabase functions deploy daily-distribution-cron --no-verify-jwt  # called by an external scheduler
```

## Secrets to set (`supabase secrets set KEY=value`)

| Secret | Used by |
|---|---|
| `RAZORPAY_KEY_ID` | razorpay-create-order |
| `RAZORPAY_KEY_SECRET` | razorpay-create-order |
| `RAZORPAY_WEBHOOK_SECRET` | razorpay-webhook (set this to match the secret you enter in Razorpay Dashboard → Webhooks) |
| `R2_ACCOUNT_ID` | r2-presigned-upload, r2-delete-photo |
| `R2_ACCESS_KEY_ID` | r2-presigned-upload, r2-delete-photo |
| `R2_SECRET_ACCESS_KEY` | r2-presigned-upload, r2-delete-photo |
| `R2_BUCKET_NAME` | r2-presigned-upload, r2-delete-photo |
| `CRON_SECRET` | daily-distribution-cron (only if you use an external scheduler instead of pg_cron) |

`SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are injected automatically — don't set
those yourself.

## Wiring it into the app / admin panel

- **Supabase URL + anon key** go into both the Expo app and the admin panel's env config
  — same values Supabase gives you under Project Settings → API.
- **Registration Step 1** (religion, caste, location, etc. dropdowns) reads straight from
  the lookup tables, which are world-readable — no login needed.
- **Profile creation** inserts into `profiles`; the `trg_after_profile_insert` trigger
  fires automatically and puts the user on the Free plan + runs their first distribution.
- **Buy a plan**: app calls `razorpay-create-order`, opens Razorpay Checkout with the
  returned `order_id`/`key_id`, then just waits — the webhook does the actual activation,
  so poll `user_dashboard_summary` (or subscribe via Supabase Realtime on
  `user_subscriptions`) to know when it's gone through.
- **Upload a photo**: app calls `r2-presigned-upload`, `PUT`s the file to the returned
  `upload_url`, then inserts a row into `profile_photos` directly via the Supabase client
  using the returned `r2_key`.
- **View phone/horoscope**: app calls the `fn_view_contact_credit` RPC.
- **Send/accept/reject interest**: `fn_send_interest` / `fn_respond_interest` RPCs.
- **Admin panel**: every `fn_admin_*` RPC and the `admin_stats_view` / `revenue_summary`
  views return real data only when the caller's `auth.uid()` has a row in `admin_users`
  — create that row manually for your first admin account (via SQL editor or a one-off
  script) since there's no self-serve signup path into `admin_users` by design.
- **Distribution Management screen**: reads/writes `distribution_config` directly
  (admin-only via RLS) and can trigger `fn_admin_manual_push` for the "push now" button.
